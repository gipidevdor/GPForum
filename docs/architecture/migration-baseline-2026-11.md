# Fresh-database baseline: comparison and verification

The owner chose a new, empty database on 2026-11-01. This implements
[ADR 0162](../adr/0162-a-fresh-database-baseline.md): the migrations describe
what the forum needs now, instead of replaying the development history.

## Size and organization

| | Previous chain | New baseline |
| --- | ---: | ---: |
| SQL files | 66 (1000–1065) | 26 (2000–2025) |
| SQL lines | 32,555 | 23,299 |
| API function definitions installed | 923 | 769 |
| Versions retained only for older workers | 154 definitions | 0 |

The reduction is 40 files and 9,256 SQL lines (28.4%). Primary/unique/check
constraints and indexes live beside their table; foreign keys follow the
completed tables; implementations are grouped by area; typed entry points
come last. There are no column/index replacement steps, historical data
backfills or `CREATE OR REPLACE FUNCTION` exceptions. Function-body validation
stays enabled throughout installation.

The API version suffixes and the current catalogue remain unchanged. A typed
owner-rights wrapper and its invoker implementation are not duplicates to
remove: together they enforce the runtime role's restricted access.

## Database comparison

On a private PostgreSQL 18.6 cluster, build the previous chain using
`GPForum::Command::Migrate`, including its partition window and budget sync.
Clone it and trace API references from all 328 current catalogue entries and
the two API trigger functions. Remove only the 154 unreachable definitions
from that clone, using explicit signatures and ordinary restrictive drops.
No `CASCADE` is needed.

Build another empty database through the same migration command, using the
new baseline. Compare sorted `script/schema-fingerprint` output:

| Comparison | Facts removed | Facts added |
| --- | ---: | ---: |
| Previous chain → clone without obsolete functions | 308 | 0 |
| Reference clone at the same plugin feature level → new baseline | **0** | **0** |

While this work was running, the Wikipedia plugin work added `wikipedia` to
`core_configuration_valid_v1`'s accepted plugin keys. That is a separate,
known feature change. Apply that same one-function change to the reference
clone before the final comparison; it is not attributed to consolidation.
Both full normalized schema dumps then also match byte for byte, including
text-search mappings and extension-function ACLs that fingerprints omit.
The trigram extension is installed before private function defaults, as it
was in the old chain, preserving its existing privileges.

The 308 removed facts are exactly 154 function contracts and their 154 body
hashes. The remaining **3,869 facts match exactly**: schemas/extensions,
relations, column order and types, defaults, storage options, constraints,
indexes/predicates, grants, triggers, API row types, function signatures,
settings and body hashes. No query, constraint, permission or index is changed
as an optimization guess.

Creation timestamps and the migration ledger are naturally different data.
The baseline initializes the same open registration policy and empty forum
configuration. Partition registry rows and endpoint budgets are generated by
the migration command, not copied as historical seed data. Running the command
again is a no-op, and old migration histories are refused before SQL runs.

## Regression coverage

`t/641-sql-function-migrations.t` and the live catalogue test now start only
from current entry points and triggers; there is no retained-version
allowlist hiding unreachable functions. The static audit exception is removed.
Migration plan/doctor/front-door tests use the new range; the migration runner
test verifies rejection of the 1000–1065 chain. Poll tests replace the retired
worker-version scenario with a current-API ballot replacement, retaining its
counter and extra-choice assertions. The canonical PostgreSQL 18 schema
snapshot is regenerated from the baseline.

The initial baseline run exercised 494 unit files (18,743 tests) and 145 integration
files (13,126 tests). All baseline-specific failures were corrected and
rechecked. At that stage, three integration failures remained in public-cache query counts,
query budgets and the second-factor page; the same failures reproduce with
the former migration chain and the same application code. Seven unit files
failed on unrelated presentation/catalogue/preamble/composition checks.
The retired-indexer scenario in Italian search was then changed to damage
and rebuild a current document; its 26 assertions pass.

The final focused run passes **783 assertions in seven unit files** and
**8,355 assertions in 31 integration files**, including schema snapshots,
restricted-role contracts, the installation flow, Italian search, polls and
privacy.

The SQL benchmark smoke passes on the local Unix socket. Formatting and
Perl::Critic pass for the changed Perl files. The fingerprint and full-dump
comparisons above independently establish schema preservation.

## Consolidation follow-up (2026-11-02)

The [consolidation review](../QUALITY_PROGRAM.md#consolidation-review-2026-11-02)
closed the application/test failures recorded above without changing the SQL
baseline. The full unit tier now passes **495 files and 18,787 tests**; the full
PostgreSQL tier passes **145 files and 13,162 tests** on temporary Unix-socket
clusters. Browser clients pass 73 tests and the performance evidence contracts
pass 289 tests in 11 files.

The configuration feature deliberately adds one authoritative lookup before
public-cache access; cached pages make no forum-content query. Query budgets
now count that read and the signed-in profile's private follow state explicitly,
with page-length independence preserved. The same test now verifies the real
runtime observer, correcting five stale endpoint limits that previously
rejected pages even when raw-count checks passed. The second-factor page assertion
distinguishes an obsolete enrollment QR from ordinary icons. Italian-search
fixtures declare UTF-8, and the preamble/composition/translation/documentation
checks match the current features. These fixes resolve the prior regression
failures; they do not replace the independent schema comparison above.
